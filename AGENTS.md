# Design MCP development

Use the [Design MCP harness](DESIGN-HARNESS.md) for feature work, sources, and releases. Keep the approved scope and proof requirements in [PLAN.md](PLAN.md). Record measured outcomes and open gates in [EVALS.md](EVALS.md) and [LEDGER.md](LEDGER.md).

Give each meaningful change a testable acceptance contract before editing. Keep the builder, independent evaluator, and blind visual critic separate. Verify the main action and relevant edge cases in Playwriter. Use GPT Computer Use for the final native browser flow. Preserve the strongest verified iteration.

Check current public sources when a claim, design direction, browser dependency, or competing tool may have changed. Review the recurring source queue for candidates. Promote only changes with verified sources, a relevant held-out result, and a written decision. Follow the owner's shared-machine, spend, credential, and branch rules.
