# Design MCP research notes

**Test retrieval first.** Give the same web brief to the same generator with four kinds of context: none, generic design guidance, a randomly selected pattern, and a pattern retrieved for that brief. WebViSE provides direct evidence that matching the pattern matters. RefCraft shows a different effect: when a brief explicitly refers to an image, access to that image can determine whether the generator understands the request. These deserve separate experiments. [WebViSE, Table 2](https://arxiv.org/html/2610.33929v1) · [RefCraft, Table 2](https://arxiv.org/html/2610.26826v2)

The 14 sources below are ranked by priority for Design MCP. The middle column reports published evidence. The final column gives a proposed adaptation and a measurable local hypothesis.

| Rank and source | What the source established | Design MCP adaptation and expected gain |
|---|---|---|
| 1. **WebViSE** · Sun et al., 2026 preprint | The authors extracted 864 reusable design patterns from 850 websites. Across seven generators and 350 blinded website pairs, retrieved guidance earned preference margins of **12–34 percentage points** over the base generator. Each pair received one judgment. For Claude Opus 5, WebGen-Bench accuracy was 56.80% with no guidance, 50.70% with random patterns, and 60.05% with retrieved patterns. [Table 2 and Appendix C.5](https://arxiv.org/html/2610.33929v1) | Return a small pattern with its intended use and implementation details. Against equal-length generic and shuffled guidance, expect a higher blinded preference margin on original briefs. Track functional pass rate alongside preference. |
| 2. **RefCraft** · Wang et al., 2026 preprint | Its 300 tasks combine a brief with one to five reference webpages. With the text held fixed, supplying the referenced images raised GPT-6 Astra’s overall score from **17.3 to 52.1** and DeepSeek-V4-Pro’s from **11.1 to 37.1**. These briefs explicitly depended on their references. [Table 2 and §5.3.2](https://arxiv.org/html/2610.26826v2) | Attach each reference to the property the user wants to borrow, such as “type hierarchy from A, table density from B.” Against the same images supplied without labels, expect more requested properties to appear and fewer incidental details to carry over. |
| 3. **Design2Code** · Si et al., NAACL 2025 | The benchmark contains 484 real webpages plus a separate 80-page hard set. On the hard set, GPT-4o’s Block-Match score was **56.6** from the screenshot alone, **67.7** with text extracted from the original page, and **72.1** after visual revision. Claude 3.5 Sonnet went from **75.1 to 71.9** on that last step. [Table 3](https://aclanthology.org/2025.naacl-long.199.pdf#page=8) | Supply exact copy when the brief or design file provides it. Compare the first render with the revision against a list of required regions. Expect fewer missing text blocks on dense pages. Record how often revision makes the first render worse. |
| 4. **Figma2Code** · Gui et al., ICLR 2026 | Designers curated 213 benchmark cases from 3,055 samples. Under direct prompting with ERNIE 4.5 424B VL, adding Figma metadata to the image raised visual embedding similarity from **0.5653 to 0.6923**. The absolute/fixed positioning ratio also rose from **0.01% to 2.83%**. [Table 3](https://arxiv.org/html/2604.13648v1) | Return parent-child layout, alignment, spacing, and wrapping rules alongside the screenshot. Compare this with raw geometry plus the same screenshot. Expect fewer overflows at an unseen width while preserving desktop fidelity. |
| 5. **WebGen-Agent** · Lu et al., 2025 preprint | In the WebGen-Bench workflow ablation, adding screenshot feedback to execution feedback raised the appearance score from **3.0 to 3.6**. Adding interaction testing then raised functional accuracy from **46.6% to 49.9%**, while appearance fell to **3.4**. [Table 2](https://arxiv.org/html/2509.22644) | Pair visual critique with one observable user outcome, such as a saved edit surviving navigation. Against screenshot-only critique, expect more passing interactions. Keep both renders so reviewers can also detect visual regressions. |
| 6. **Design Tokens Format Module 2025.10** · Design Tokens Community Group, 2025 | This interoperability specification defines typed token values, inherited types, and aliases. A `{group.token}` reference resolves to the target token’s complete value. Circular references are invalid. Its contribution is a testable data contract. [Format module, §§7–8](https://www.designtokens.org/tr/2025.10/format/) | Return the semantic token name, resolved value, and existing code identifier together. Compare with a flat palette on a theme-switch task. Expect more eligible declarations to use the correct semantic token and fewer components to require manual edits after the switch. |
| 7. **RepoCoder** · Zhang et al., EMNLP 2023 | On RepoEval’s Python API-call completion task, GPT-3.5-Turbo exact match rose from **34.06%** with in-file context to **47.69%** after one retrieval pass and **49.19%** after two. The second query uses the draft completion. [Table 2b](https://aclanthology.org/2023.emnlp-main.151.pdf#page=6) | Use a draft component name to retrieve its actual import, props, and one call site from the project. Against one retrieval pass, expect fewer nonexistent imports and invalid props in generated UI code. |
| 8. **UICrit** · Duan et al., UIST 2024 | Seven designers supplied 3,059 critiques for 983 mobile UIs. In a six-person evaluation, task- and visually matched examples plus coordinate prompts raised average localized comment quality from **0.31 to 0.48**. Human critiques scored **0.75**. The scored unit was a critique comment. [Table 7](https://arxiv.org/html/2407.08850) | Have the critic identify a visible region, its defect, and a proposed correction. Against free-form critique, expect a larger share of comments to identify the reviewer-labeled element correctly. Score whether the subsequent edit fixes it as a separate outcome. |
| 9. **Vision2Web** · He et al., 2026 preprint | Its 193 tasks span static, interactive, and full-stack sites. On the static tasks, Gemini-3-Pro-Preview with OpenHands scored **63.3 desktop, 55.8 tablet, and 48.3 mobile**. Each task supplied prototypes at all three sizes. [§3 and Table 3](https://arxiv.org/html/2603.26648v3) | Retrieve a component’s wide and narrow arrangements together. Compare with desktop-only guidance and score a third width withheld during generation. Expect a higher worst-viewport score and fewer clipped controls. |
| 10. **WebUI** · Wu et al., CHI 2023 | WebUI collected roughly **400,000 web pages** using six device configurations. It pairs screenshots with accessibility trees, element bounds, and computed styles. The authors split data by domain to keep pages from the same site together. [Paper](https://arxiv.org/html/2301.13280) · [Author dataset page](https://uimodeling.github.io/) | Index examples by element role and viewport as well as appearance. Against image-only search, expect a higher fraction of the top three results to match both the requested role and viewport on held-out domains. |
| 11. **Repoformer** · Wu et al., ICML 2024 | In its dense-retrieval API-completion experiment, the 1B model’s threshold policy retrieved on **61%** of examples and scored **72.39** edit similarity. Always retrieving scored **71.69**. This result concerns repository code completion. [Appendix E.3, Table 8](https://arxiv.org/html/2403.10059) | Let retrieval abstain on self-contained edits. Against always retrieving, expect fewer calls and input tokens at comparable component-validity and task-pass rates. Report those rates for the skipped cases too. |
| 12. **WebSight** · Laurençon et al., 2024 preprint | WebSight contains **2 million synthetic screenshot/HTML pairs**. The authors’ evaluation was qualitative. They report failures on dense text, complex layouts, and elements present in generated code that disappear when rendered. [§§3–5](https://arxiv.org/html/2403.09029) | Use a small sample with known markup to test whether the evaluator catches missing or invisible elements. Compare region-level checks with global image similarity. Expect higher defect recall at the same false-positive rate, then measure transfer on real pages. |
| 13. **Rico** · Deka et al., UIST 2017 | The original paper reports **72,219 unique UIs from 9,772 Android apps** across 27 categories. Screens, view hierarchies, and interaction traces supported a demonstration of layout search by example. [Original paper](https://danafergan.com/publications/deka2017rico.pdf) | Use its hierarchy for mobile navigation and list-detail examples, retaining the Android platform label. Against screenshot-only search, expect more relevant top-three layouts on mobile briefs. Check whether Android-specific controls leak into desktop results. |
| 14. **Harness²** · Xu et al., 2026 preprint, arXiv 2610.14224 | One propose–probe–compose step yielded maximum gains of **11.5 points** on WorkBuddy-Bench’s Code/Web/Office average, **4.5 points** on JobBench professional deliverables, and **11.8 percentage points** on Harvey’s Legal Agent Benchmark criterion pass rate. WorkBuddy’s Web subset includes page interaction, data visualization, and document conversion. Screenshot fidelity and aesthetic preference require their own UI evaluation. [Tables 1–2 and Appendix B](https://arxiv.org/html/2610.14224v1) | After a recurring UI failure, compare one general rule and one component-specific fix against the frozen baseline. Expect fewer repetitions of that defect on unseen site families at the same generation budget. Use that held-out result to decide which rule to keep. |

**First evaluation.** Hold out entire site and template families from retrieval and tuning. Freeze the generator, assets, and token and tool-call budgets. For original briefs, randomize the order of each output pair, allow ties, and report the preference margin as **100 × (wins − losses) / all pairs**. For reference briefs, score the requested visual properties at desktop and mobile widths. For interactive briefs, check the resulting application state. Report paired differences by brief alongside actual tokens and latency. That gives the project a way to tell whether retrieval improved the design, preserved the reference, or helped a user finish the task.

## Follow-ups from the recurring source scan

The installed Design Library comparison found matches for 34 of 36 full briefs with hybrid search and zero with keyword search. The hybrid arm also returned three results for a nonsense query. For a Design MCP retrieval experiment, match the requested task mechanism and platform before ranking, then test abstention against unrelated briefs. Record relevance and query latency separately from catalog hit rate. [Paired retrieval and entry sample](../teardown/COMPETITORS.md#design-library-keyword-and-hybrid-on-one-install)

- **Rubrics as Visual-Repair Context.** The authors generate candidate repairs, select one under an edit budget, and pass the selected repair and history to the generator. In their screenshot-to-code task, this stabilized revision outcomes. Test that policy against unrestricted revision from the same initial pages. Track the target region and any previously passing interaction. Reject a revision that fixes its target but breaks the earlier task. [Method and experiments](https://arxiv.org/html/2608.24138v1)
- **WebUIProof.** The preprint reports frequent interaction failures on pages that rendered successfully. For each browser action in our holdouts, record the starting state and an assertion about what changed, including focus or persistence when the task depends on it. Compare these assertions with screenshot-only review on the same generated pages and count the failures each method catches. [Paper](https://arxiv.org/abs/2610.02617)
- **Pattern over Pixels.** Five models regularly completed the repeated pattern instead of preserving a deliberately different card width or font size. Small differences were harder to detect. The authors tested one-shot CSS completion on 30 sites. Test one intentional width or type-size exception in a held-out task. Give both arms the same image and one arm the relevant bounds or CSS value. Count how often each preserves the exception in the actual render. [Results and limitations](https://arxiv.org/html/2608.03691v1)
- **Render Structure Uncertainty.** The abstract describes tracing a visual mismatch to several plausible DOM subtrees, then rendering local alternatives in the whole page. Use that idea when the visible defect could come from either the component or its parent layout. Compare one locally verified change with a full-page rewrite and record the target improvement, adjacent region drift, and the primary interaction outcome. [Harvard repository and indexed abstract](https://openalex.org/W7225436441)
- **Design Theater.** The authors evaluated whether five generative UI tools implemented the design decisions described to users. Their study found missed commitments especially in functionality. For the release form, compare the planned affordances with browser evidence after an invalid submission and a valid one. Count a commitment as verified only when the promised behavior appears in the corresponding state. [Paper and evaluation method](https://arxiv.org/html/2607.22928)
- **TaoD2C-Bench.** The study found visually similar outputs that violated component, positioning, or grouping requirements. Test mobile crop and wrapping as geometry assertions alongside the live visual ballot. For River Gauge, compare the rendered image aspect ratio with the exported frame and measure the selected guide against the corresponding image contact. [Findings and examples](https://arxiv.org/html/2610.10374)

The November 22 scan returned both of these papers through OpenAlex. Their first local application is the recorded test contract. Shipping a new generation instruction still requires a matched improvement on a held-out brief. [Recurring source review](../.github/workflows/design-source-review.yml)

**Rubrics as Visual-Repair Context.** RubSE selects typed repair criteria before revising code. Its ablation links repeated spacing and density edits to missed opportunities to fix missing or misplaced elements. The authors also report higher API cost for their multi-call workflow. The booking experiment tests a smaller adaptation using the existing `react` call. It puts the result placement in its own field and checks the updated value in the post-selection viewport. Count the change only when the generated repair preserves booking behavior and the result is visible after both keyboard and pointer selection at all three widths. [Paper, Appendices B.3 and B.4](https://arxiv.org/html/2608.24138v1)

## Interaction craft checks for the release candidate

| Primary example | Mechanism to test | Acceptance observation |

| Linear's interface redesign | Establish the hierarchy in neutral tones, then introduce the accent after checking which surface or control should lead. Stress-test the navigation in browser and native window arrangements. | A reviewer can locate the selected result and primary action with accents suppressed. | Rauno Freiberg's interaction essay | Use gesture feedback while the person can still change their mind. Commit a consequential action when intent is clear, and keep input methods intentional. | For a preview slider, Escape or an interrupted gesture keeps the prior committed value. Enter and pointer release commit the same selected state. Capture the intermediate and committed states separately. | Emil Kowalski's dropdown example | Derive the animation origin from where the menu actually opens relative to its control. | Trigger the same menu with room below, then near the lower edge so it flips above. The first River shoreline ballot gives a local check on the hierarchy idea. Correcting the geometry raised the matched score from 8.15 to 8.25 at both widths. At 2 m, two status-free rows still looked like closures. The next comparison tests a list of affected crossings only and separates nearby map labels. Keep the 6 m and 2 m keyboard results and compare the exact rendered states. [Audited live comparison](../evidence/benchmark-v1/social-river-shoreline-geometry-first.json)

**DesignCoder.** The published method groups the functional regions of a design mockup, generates the corresponding subtrees, and checks the rendered result. Test its grouping idea on a page-review update with one control that changes neighboring statuses. Give both arms the same masked screenshot. In one arm, include the control's label, role, surrounding heading, geometry and affected regions. Compare how often the repair hits the intended region and keeps the keyboard action intact. The paper reports fidelity against annotated mockups, so this checkpoint measures repair accuracy alongside the separate visual ballot. [Published paper](https://www.sciencedirect.com/science/article/pii/S095058492600203X) · [Authors' project](https://bloomberry.github.io/DesignCoder/)

## Keep implementation recommendations current

For framework-dependent advice, read the target project's manifest and lockfile first. Retrieve the official documentation for the installed version and one existing call site. Give the builder only the relevant API excerpt and the browser acceptance test. Skip retrieval for self-contained CSS adjustments when the repo already has a suitable pattern. Compare version-matched retrieval, generic retrieval and the existing implementation on the same held-out tasks. Count wrong APIs, unnecessary dependencies, task passes and total time and tokens. Apply Harness²'s propose, probe and retain loop to one change at a time. [RepoCoder](https://aclanthology.org/2023.emnlp-main.151/) · [Repoformer](https://arxiv.org/abs/2403.10059) · [Harness² project](https://github.com/google-research/harness2)

OpenAI’s Codex engineering account and Anthropic’s programmatic tool calling share a practical mechanism. Let a deterministic program read the full browser trace and pass only the findings needed for the current decision. Keep source excerpts keyed to the installed dependency version and attach one reproducer, the assertion, and the patch location. Keep the raw trace and full images for independent evaluation. Test this against passing the entire trace on the same task. The outcome must preserve fault identification and task completion while lowering total input, including any extra evidence requests. The providers’ savings came from their own workloads. [OpenAI harness engineering](https://openai.com/index/harness-engineering/) · [Anthropic advanced tool use](https://www.anthropic.com/research/advanced-tool-use)

## November 23 execution and feedback research

- **WebUIProof** defines 219 general UI and interactive 3D tasks with structured specifications and executable interactions. Its functional benchmark gives us an independent check for visually rich work. Apply that to rapid level reversal, correct closure state and keyboard focus in River before accepting any critique score. Expected change: reject visually convincing builds whose default or transition states disagree. Falsifier: an intentionally stale 6 m marker passes the scripted and blind 2 m checks. This transfer is a test hypothesis. [Paper and protocol](https://arxiv.org/abs/2610.02617)
- **RubSE** selects a single typed visual discrepancy per pass and retains its repair history. Follow the same revision discipline for a strong premise: provide one observation with a screen, state, and pass condition. Reassess the already-correct states after the change. Expected change: fewer regressions such as state labels advancing ahead of the image. Falsifier: the same stale-image or obscured-path problem recurs in a matched replay. The research measures visual reconstruction. Creative-site originality still needs the independent live rubric. [Project and paper](https://tyxiong23.github.io/rubse/)
